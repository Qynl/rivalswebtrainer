# Restore the earlier movement baseline

The user rejected further compromise tuning and explicitly selected **“Bring the old movement back.”** This revision restores the non-slide locomotion values from **`bf18246`** (also present immediately before `7b25612`), while retaining the later requests for instant slide starts, a long glide and jump-to-cancel. This is a targeted physics restoration, not a repository rollback.

## Restored values

| Setting                                             |       Last compromise |    Restored earlier value |
| --------------------------------------------------- | --------------------: | ------------------------: |
| Running / melee speed                               |            9.6 / 10.8 |             **10.6 / 12** |
| Ground acceleration / braking / counter-strafing    |       100 / 125 / 130 |       **105 / 135 / 155** |
| Air acceleration / turn rate / reverse acceleration |           28 / 6 / 60 |         **34 / 7.5 / 75** |
| Jump / extra jump impulse                           |             7.8 / 7.6 |             **9.7 / 9.4** |
| Flat jump apex / airtime                            | 1.014 units / 0.520 s | **1.568 units / 0.647 s** |
| Ramp assistance factor / cap                        |            0.10 / 0.8 |            **0.18 / 1.5** |
| Added slide speed / speed cap / turn rate           |        1.6 / 13 / 3.6 |      **2.4 / 16.5 / 3.8** |

These numbers are read from that historical source, rather than invented as a new approximation. The original acceleration algorithm is still used, with the later exact-target floating-point cleanup retained. Gravity, collision, headroom, coyote/jump buffering and momentum-preserving slide jumps use the same shared solver. There is no hidden second jump/slide launch.

## Explicitly retained newer behavior

- Ground slides start immediately, including at rest; no minimum running speed or post-slide cooldown.
- Up to **1.5 seconds** of slide time. The newer no-input coasting and forward/lateral cruise are intentionally retained, rather than restoring the old short, high-drag slide. A running slide now enters at **13**, versus the compromise's 11.2; stationary entry remains 10.4.
- Jump cancels immediately, retaining horizontal momentum. Airborne taps can buffer a slide on landing; stale requests expire. Extra slide presses during an active slide do not refresh time or apply another boost.
- Reliable/unreliable traffic separation, monotonic remote playback, historical reconciliation and coalesced input remain unchanged. Both players should refresh and create a fresh lobby because their movement tuning must match.
- Invert mouse Y, stable aim, restrained camera motion, weapon visuals, health/ammo/damage and offline bots are not rolled back. Bots receive the same restored jump/ramp/air/slide helpers while retaining difficulty-specific navigation, combat decisions and speeds.

## Evidence and validation

`tests/fixtures/earlier-movement.json` was generated by executing **`bf18246:src/movement.js`** against the deterministic replay in `tests/helpers/movement-replay.js`. Its full source commit is recorded in the fixture. It contains the historical non-slide constants and ground start/stop/reversal plus airborne turn/reverse checkpoints at **30, 60 and 144 Hz**. Five new tests assert the restored constants, compare these actual historical trajectories with tolerance 1e-8, and lock in the intended newer slide exceptions. Normal test execution uses the checked-in fixture and does not require Git or a historical checkout. This compares the locomotion algorithm, not two complete historical builds or hardware FPS.

**540/540 unit tests and the production build pass.** Existing jump-apex, ramp, movement-distance and authority assertions were updated explicitly for the restored profile; anti-stacking, standing starts, cancellation, held-key behavior, exact camera aim, frame-rate invariance, explosive carry, mouse inversion and multiplayer authority tests remain in place. The clean browser run passed **7/7 scenarios in 2.1 minutes**: actual standing C/Shift starts and cancellation, live jump/slide/landing-buffer and aim/FOV behavior, stairs and collision, disconnected production reload, static-only invite/play/leave, six-client RTC firing and adverse-network host/guest movement. The initial run caught an incorrectly estimated test bound for the restored running distance; the assertion now uses its analytical 8.0325-unit result (six 60 Hz acceleration ticks plus 42 full-speed ticks), and all seven cases were rerun cleanly.

In the clean delayed/lossy RTC sample, host travel was **34.078 units**, guest **33.534** (about **1.60% less**), with **zero backwards steps** and maximum horizontal corrections **0.082 / 0.274 units**. The six-client firing case kept traces/impacts off reliable combat control. These are controlled local transport/physics checks with frozen rendering and local test signaling, not public Internet/relay availability or hardware-FPS guarantees. The separately published external site has not been verified as redeployed.
